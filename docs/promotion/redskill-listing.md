# RedSkill / GitHub 展示包

本页是“专利君｜证据优先专利工作流”的公开宣传候选稿，供 GitHub README、RedSkill 笔记和人工发布清单复用。它不是小红书官方规范，也不是平台审核承诺；提交前应以 RedSkill 实际界面、账号状态和平台规则为准。

## 定位

专利君不把自己包装成“自动写专利”的工具，而是一个先核对证据、再整理交底资料的工作流。对外只承诺可检查的动作：

`资料盘点 → 来源定位 → 证据分类 → 发明点/权项限定 → 溯源检查 → 人工复核包`

## README 的字数和层级

README 不宜把营销话术铺满首页。建议把首屏介绍控制在约 800–1500 个中文字符：一句承诺、一个四行输入/输出表、一个脱敏案例、一个安装入口和一条法律/保密边界；本仓库已有的完整技术说明可以保留在约 8000–12000 字符的下层，数据契约、十阶段流程和校验细节继续放到链接页。这样 GitHub 新访客先看懂价值，专业读者再沿链接核验，不会用过多营销文字覆盖证据规则。

RedSkill 的条目更短：标题 20–28 字左右，一句话简介约 80–120 字，配 3 张图即可。字数是编辑目标而非平台承诺；平台字段如有变化，以发布界面为准。

不写“保证授权”“提高通过率”“零幻觉”“替代专利代理师”，不展示真实申请号、客户名称、内部图纸、未公开参数、供应商信息或实测性能结果。

## 案例选择与脱敏规则

推荐讲一个“脱敏长板夹持工装”合成教学案例，因为它能同时展示结构关系、证据分级、附图同源和待验证效果，但不会暴露真实项目。

公开案例只保留以下抽象事实：板件由下方承托件支撑，上方压持件通过弹性元件提供预紧，多个视图来自同一结构账本。以下内容必须删除或改写：

- 真实尺寸、材料、螺纹规格、零件编号组合、孔位坐标和制造公差；
- 真实图纸、照片、CAD 截图、供应商和客户名称；
- “翘曲减少多少”“良率提高多少”等未经公开、未经测量或尚未复核的结果；
- 申请号、发明人、代理机构、临界日和任何可反推出申请策略的组合。

公开案例应明确写出：这是合成或脱敏教学材料，不是用户的真实案件，不作新颖性、侵权、权属、授权或适合直接申请的判断。

## 角色和文案搭配

专利君只做“证据核对员和路线向导”。人物拿放大镜表示查来源，夹板表示记录证据，工程服表示技术场景；人物不穿法袍、不拿法槌、不出现天平、公章、政府纹章、奖杯或第三方商标。

适合放在人物旁边的短句：

- 先找证据，再写结论。
- 这是目标，不是结果。
- 每个限定，都要有出处。
- 证据不足，先停在人工复核。
